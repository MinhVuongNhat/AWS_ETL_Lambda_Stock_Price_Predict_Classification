#### Summary Report: "FCAJ 8 Đội Tranh Hùng – Inter-team Cloud Knowledge Battle (Qualifying Round)"

##### Event Objectives
- Reinforce and test participants' knowledge of AWS Cloud services and architecture through a competitive team quiz format.
- Encourage collaboration and fast-thinking under pressure.
- Create an engaging, gamified learning experience for all 8 participating teams.

---

#### Event Format

The **"Tranh Hùng"** competition is a structured inter-team knowledge battle involving **8 teams** competing in a round-robin quiz format:

| Rule | Description |
|:---|:---|
| **Format** | Teams take turns answering AWS Cloud technical questions |
| **Scoring** | +1 point for each correct answer |
| **Penalty** | -1 point for incorrect answers (negative scoring to encourage accuracy) |
| **Questions** | Covering AWS services, architecture patterns, cloud security, and best practices |
| **Objective** | Teams accumulate the highest score to qualify for the grand final |

---

#### Key Highlights

**Competition Structure**
- 8 teams compete simultaneously in a rapid-fire question-and-answer format.
- Questions spanned multiple AWS domains: compute (Lambda, EC2), storage (S3), databases (DynamoDB, RDS), networking (VPC, API Gateway), security (IAM, WAF), and monitoring (CloudWatch).
- The negative scoring rule incentivized teams to think carefully before answering, rather than guessing blindly.
- Eliminated teams were still encouraged to remain engaged and learn from the ongoing rounds.

**Notable Question Topics**
- AWS Lambda concurrency limits and reserved concurrency configuration.
- S3 storage classes and lifecycle policies (Standard, Intelligent-Tiering, Glacier).
- IAM permission boundary vs. Service Control Policies (SCPs).
- DynamoDB partition key design and hot partition avoidance.
- Differences between API Gateway REST API, HTTP API, and WebSocket API.
- CloudWatch metrics, log groups, and alarm configuration.
- VPC subnet routing: public vs. private subnets, NAT Gateway.

---

#### Key Takeaways

- **Breadth of knowledge matters:** The competition revealed gaps in knowledge that are not often encountered in day-to-day project work — reinforcing the importance of studying AWS broadly, not just the services used in the current project.
- **Accuracy over speed:** The penalty scoring system taught a valuable lesson: in cloud architecture, hasty decisions can be costly. Deliberate reasoning is more valuable than fast guessing.
- **Teamwork under pressure:** Quickly aligning on an answer as a team requires clear communication and defined decision-making roles — skills directly applicable to real cloud projects.
- **Knowledge diversity within the team:** Different team members had stronger knowledge in different AWS domains — recognizing and leveraging these specializations is key to team performance.

---

#### Applying to Work
- Identified personal knowledge gaps in AWS networking (VPC routing, NAT Gateway) and security (IAM policy evaluation logic) — areas to study before the grand final.
- Reinforced understanding of DynamoDB data modeling — directly applicable to the `NasdaqStockPredictions` table design in our project.
