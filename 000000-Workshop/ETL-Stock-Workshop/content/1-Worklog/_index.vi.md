#### Nhật ký công việc

*Nhật ký công việc 8 tuần — ghi lại tiến độ chi tiết, công việc đã hoàn thành, các vấn đề/thách thức kỹ thuật gặp phải và giải pháp xử lý trong quá trình xây dựng dự án Big Data ETL Pipeline & Machine Learning trên AWS.*

---

| Tuần | Công việc thực hiện (Task & Deliverables) | Trạng thái | Vấn đề / Vướng mắc gặp phải (Issues & Challenges) | Giải pháp / Bài học kinh nghiệm (Solution & Takeaway) |
|:---|:---|:---:|:---|:---|
| **Tuần 1** | **Khởi tạo dự án & Xây dựng pipeline Ingestion ban đầu**<br>• Thiết lập thư viện Python (Polars, YFinance, Boto3).<br>• Viết script thu thập dữ liệu cổ phiếu NASDAQ từ Yahoo Finance API (`yfinance`).<br>• Lưu trữ dữ liệu thô (Raw Data) dưới dạng CSV/Parquet ban đầu. | `Completed` | • Tốc độ thu thập hơn 3,000 mã cổ phiếu bằng `pandas` rất chậm.<br>• API Yahoo Finance bị rate limit / timeout khi gọi liên tục. | • Chuyển sang sử dụng **Polars** thay cho Pandas giúp tăng tốc độ xử lý 10-50x.<br>• Áp dụng chia nhỏ danh sách (batch/chunking) và xử lý bất đồng bộ. |
| **Tuần 2** | **Thiết kế Kiến trúc AWS Cloud & S3 Bucket Layering**<br>• Cấu hình tài khoản AWS IAM, S3 Buckets.<br>• Phân chia kiến trúc lưu trữ 4 tầng: `raw/`, `cleansed_daily/`, `processed/`, `quarantine/`.<br>• Viết module `s3_service.py` tương tác với S3. | `Completed` | • Gặp khó khăn khi quản lý cấu trúc file Parquet lưu trữ dữ liệu lịch sử từ 1962 đến nay.<br>• Quản lý dung lượng & chi phí đọc/ghi trên S3. | • Thiết kế lưu trữ dữ liệu lịch sử theo từng năm (`processed/YYYY.parquet`) giúp tối ưu truy vấn.<br>• Sử dụng định dạng **Parquet** nén Snappy tối ưu kích thước lưu trữ. |
| **Tuần 3** | **Xây dựng Data Quality Gate & Quarantine Mechanism**<br>• Viết module `validator.py` kiểm tra Schema & Data Quality.<br>• Xây dựng `quarantine.py` cách ly dữ liệu lỗi.<br>• Đóng gói và deploy `lambda_quality_gate.py`. | `Completed` | • Dữ liệu từ Yahoo Finance hay có lỗi: thiếu giá (null/NaN), giá âm, ngày trùng lặp, mất phiên giao dịch.<br>• Dữ liệu lỗi tràn vào file chính làm hỏng tính toán indicator. | • Định nghĩa các quy tắc kiểm tra nghiêm ngặt (Quality Gate).<br>• Tự động đẩy file lỗi vào S3 `quarantine/` kèm log lý do để debug mà không làm gián đoạn pipeline. |
| **Tuần 4** | **Phát triển Feature Engineering Engine với Polars**<br>• Thiết kế module `transform.py` tính toán 16 chỉ báo kỹ thuật.<br>• Các chỉ báo: SMA (10, 20, 50), EMA, RSI, MACD, Bollinger Bands, Volatility, Price Lags.<br>• Định nghĩa nhãn dự đoán Target (`Target_Return_1D_Class`). | `Completed` | • Tính toán chỉ báo kỹ thuật trên chuỗi thời gian (Time-series Window Functions) phức tạp khi dữ liệu bị khuyết ngày.<br>• Tránh hiện tượng Look-ahead Bias (rò rỉ dữ liệu tương lai). | • Dùng Window functions của Polars theo `Ticker` và sắp xếp đúng thứ tự `Date`.<br>• Kiểm tra kỹ lưỡng các hàm Shift/Lag để đảm bảo tính toán feature chỉ dựa trên dữ liệu quá khứ. |
| **Tuần 5** | **Xây dựng kiến trúc Serverless Fan-Out (AWS SQS & EventBridge)**<br>• Viết `lambda_daily_collector.py` (Producer) đọc `tickers.json` và chia message vào SQS Queue.<br>• Viết `lambda_collector_producer.py` (Consumer) nhận message từ SQS và tải data.<br>• Cấu hình AWS EventBridge Cron công việc tự động chạy hàng ngày. | `Completed` | • AWS Lambda bị **Timeout 15 phút** khi tải dữ liệu cho toàn bộ 3,000+ cổ phiếu NASDAQ cùng lúc.<br>• Một số Lambda Consumer thất bại làm mất dữ liệu chunk đó. | • Áp dụng **Fan-Out Pattern**: Producer Lambda chia mã cổ phiếu thành các chunk nhỏ (ví dụ 50 mã) đẩy vào **AWS SQS Queue**.<br>• Nhiều Lambda Consumer chạy song song xử lý từng message.<br>• Cấu hình DLQ (Dead Letter Queue) để hứng các message lỗi. |
| **Tuần 6** | **Huấn luyện Mô hình Machine Learning (XGBoost Classifier)**<br>• Viết script `train_model.py` để train mô hình phân loại xu hướng giá (Tăng/Giảm).<br>• Chia tập dữ liệu Train/Validation/Test theo mốc thời gian (TimeSeriesSplit).<br>• Đánh giá mô hình (Accuracy, Precision, Recall, AUC, Feature Importance) và xuất `training_report.md`. | `Completed` | • Mất cân bằng dữ liệu (Imbalanced Data) giữa ngày tăng và giảm.<br>• Mô hình bị Overfitting trên tập dữ liệu lịch sử nếu không chia đúng Time-series split. | • Sử dụng **TimeSeriesSplit** thay vì K-Fold ngẫu nhiên để phản ánh đúng thực tế giao dịch.<br>• Sử dụng XGBoost với `scale_pos_weight` và tinh chỉnh Hyperparameters.<br>• Lưu artifact mô hình (`xgboost_v1.json`) lên S3 Bucket. |
| **Tuần 7** | **Xây dựng Predictor Service (AWS Lambda & API Gateway)**<br>• Viết `lambda_stock_predictor.py` nạp mô hình từ S3 và đưa ra dự đoán Real-time.<br>• Kết nối Lambda với AWS API Gateway tạo RESTful API.<br>• Tự động chọn ra **Top 5 cổ phiếu khuyên mua** (Xác suất tăng giá cao nhất). | `Completed` | • Kích thước deployment package Lambda quá lớn khi include XGBoost & Scikit-learn.<br>• Cold start delay của Lambda làm phản hồi API bị chậm. | • Đóng gói Lambda bằng **Docker Container Image** lưu trên Amazon ECR.<br>• Tối ưu dung lượng Docker image chỉ cài đặt các thư viện cần thiết. |
| **Tuần 8** | **Xây dựng Web Dashboard (Node.js/Vite) & Tài liệu Workshop**<br>• Phát triển giao diện Web Dashboard tương tác bằng Node.js, Vite & React UI (`dashboard/`).<br>• Kết nối Web Dashboard với REST API trên AWS API Gateway để hiển thị tín hiệu mua/bán real-time.<br>• Viết toàn bộ tài liệu kỹ thuật Workshop, hướng dẫn thực hành và kiểm thử toàn hệ thống (End-to-End Test). | `Completed` | • Đồng bộ dữ liệu hiển thị real-time và xử lý CORS từ API Gateway trên giao diện Web.<br>• Tối ưu tốc độ tải trang và trải nghiệm người dùng với các biểu đồ kỹ thuật tương tác. | • Cấu hình CORS trên API Gateway và xây dựng các component React hiển thị danh sách Top Cổ Phiếu khuyên mua.<br>• Đóng gói tài liệu Workshop từng step-by-step cho người đọc dễ theo dõi và thực hành. |
